Example: invoice RE-2026-0417, an XRechnung 3.0 (UBL) with two mistakes

3 errorsinvalid

Your file is XRechnung 3.0 (UBL Invoice syntax); result under KoSIT configuration 2026-08-31 (XRechnung 3.0.2), XRechnung schematron 2.6.0, CEN EN 16931 schematron 1.3.16: Invalid under the KoSIT scenario "EN16931 XRechnung (UBL Invoice)": 3 errors, 0 warnings, 0 notices.

  1. !BR-CO-10 Sum of Invoice line net amount (BT-106) = Σ Invoice line net amount (BT-131).Possible content error (BMF letter Rn. 35a) · CEN EN 16931 schematron 1.3.16
  2. !BR-CO-13 Invoice total amount without VAT (BT-109) = Σ Invoice line net amount (BT-131) - Sum of allowances on document level (BT-107) + Sum of charges on document level (BT-108).Possible content error (BMF letter Rn. 35a) · CEN EN 16931 schematron 1.3.16
  3. !BR-DE-15 Das Element "Buyer reference" (BT-10) muss übermittelt werden.Business-rule error (BMF letter Rn. 6b) · XRechnung schematron 2.6.0

The Leitweg-ID (buyer reference) is missing, and the sum of the lines is EUR 0.10 short; that second mistake breaks two calculation rules (BR-CO-10 and BR-CO-13). With JavaScript the whole invoice shows here.

How it checks

The official rules, in plain words.

The file is read in your browser; only a check or the PDF sends it to the server, where it is checked in memory and not kept.

What it does not cover

The XML Schema (XSD) step, whether the invoice is right in substance, and tax advice.

Please read
  • Checked against the official schematron rules (KoSIT configuration 2026-08-31 (XRechnung 3.0.2), XRechnung schematron 2.6.0, CEN EN 16931 schematron 1.3.16). The XML Schema (XSD) step that the KoSIT validator also runs is not run here.
  • A pass does not mean the invoice is right in substance (BMF letter of 15 Oct 2025, Rn. 35a).
  • Not tax advice. Placing errors in the BMF letter's categories is a reading aid.
  • The XML file is the invoice; the view and the PDF are reading copies.
  • Files are processed in memory and not kept. The view on the web page is made in the browser, with no upload.

The official rules, as published

The schematron files the KoSIT validator runs, with the scenario and versions named.

Read more

The check runs the schematron files the KoSIT validator runs: CEN EN 16931 version 1.3.16 and the XRechnung schematron 2.6.0, with the scenarios and severity changes of the KoSIT configuration 2026-08-31. Every result names its scenario and versions.

Every error in plain words

The official message, the business terms and where in the file, for every error.

Read more

Each error shows the official message, the business terms it names (BT numbers) and where in the file it is. The codes people search for most have a page each, in German, with the cause, the fix and an example the engine itself checks.

Sorted the way the BMF letter sorts them

Format, business-rule or content error, as the BMF letter of October 15, 2025 sorts them.

Read more

The German finance ministry's letter of October 15, 2025 tells format errors (Rn. 6a), business-rule errors (Rn. 6b) and content errors (Rn. 35a) apart. Each error is placed in one of these, as a reading aid, not tax advice.
