MCP for AI agents

Give your agent
exact tools.

Endwise runs an MCP server over Streamable HTTP. Your agent gets the same tools and the same prices as the REST API, and the same answer every time. Apps that support MCP sign-in connect with just the address; other clients use an API key.

  • Made by Conyso
  • Exact, no AI
  • Official sources, dated
  • Files you upload are not kept
  • SecurityTerms
Connect

One address
then sign in or add a key.

MCP server, Streamable HTTP
https://krishnachagti-sudo.github.io/toll-preview/mcp
Send JSON-RPC 2.0 requests with POST, one at a time. Batches are not supported.
  1. 01

    Add the server

    Give your MCP client the address above. In the Claude apps, add it as a custom connector; in ChatGPT, add it as a custom MCP server and choose OAuth.

  2. 02

    Sign in, or use a key

    Apps that support MCP sign-in (OAuth) open a Endwise page where you approve the app and set its monthly limit. For other clients, create an API key and send it as a Bearer token in the Authorization header.

  3. 03

    List, then call

    Listing tools needs nothing. Calling one needs a sign-in or a key, and is priced and limited exactly like an API call. Connected apps show on your account page next to your keys, and you can disconnect one at any time.

MCP client settings
{
  "mcpServers": {
    "tools": {
      "type": "http",
      "url": "https://krishnachagti-sudo.github.io/toll-preview/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_API_KEY"
      }
    }
  }
}

Clients that use an API key take a block like this. Put your real key in place of YOUR_API_KEY, and keep it out of shared files. A client that signs in needs only the url.

quote_price

Free. Says exactly what calling a tool with these arguments would cost this account now, without running or charging it. Give it the tool's name and the arguments you would call it with. It is listed when a tool's price depends on its input, and it answers for any tool.

Example calls

JSON-RPC over HTTP,
with real answers.

Every answer below is what the server sends back. A refused call (no balance, a limit reached, invalid input) comes back as text with isError set to true, so the agent can read the reason and act on it. A call without a sign-in or a key gets HTTP 401 with error -32001, and a WWW-Authenticate header that tells MCP clients where to sign in.
