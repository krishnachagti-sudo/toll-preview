Security answers

For your questionnaire,
answers we can give today.

Each answer is true of the running service. For a question not here, ask us and we answer it in writing. How to report a vulnerability is on the security page.

Is data encrypted in transit?
Yes. The site and the API are served only over HTTPS.
How are passwords stored?
As a salted scrypt hash, never the password itself.
How are API keys stored?
A key is shown once. We keep a hash and its first 12 characters, so a copy of the database cannot be used to make calls.
How are sessions protected?
The cookie is HttpOnly and SameSite=Lax, and only a hash of it is stored. Sign-in attempts are slowed after repeated failures.
Can a key or an agent overspend?
No. Every key has a hard monthly spending limit, and so can the account. A call past a limit is refused, not billed.
Can a call be charged twice?
No. Every charge and refund is written to the ledger in one transaction, and a retry with the same Idempotency-Key is not charged again.
Is there AI in the answers?
No. Each tool follows a fixed method over a named source. Inputs are not stored, so they are not used to train anything.
Are there third-party scripts or trackers?
No ad or analytics trackers on any page. Pages cannot be framed by other sites.
Who else receives data?
The payment provider (card and bank details) and the email delivery service (your address and the email). No one else.
How do we report a vulnerability?
Write to the security address on the security page. We reply and keep you updated.
