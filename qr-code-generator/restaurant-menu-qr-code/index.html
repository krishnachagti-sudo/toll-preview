A restaurant menu QR code that will not stop working

Print a static code that holds a page on your own domain, and update that page when the menu changes. A code for https://example.com/menu is a 25 x 25 module symbol (version 2) that no vendor can switch off.

Why menu codes stop working

Many menu codes are dynamic: they hold a vendor's short link, which stops forwarding when the plan lapses. The policies vendors publish are on static vs dynamic QR codes.

Print checks for table tents

Module size and printer dots are worked out on how big to print a QR code. Test one printed tent with a few phones before printing the rest.

Sources

  • DENSO WAVE: Points for using QR Code (quiet zone of four modules) (read 2026-11-02)
  • DENSO WAVE: Module size (4 or more printer dots a module) (read 2026-11-02)

Steps

  1. Give the menu a lasting address. Put the menu on a page of your own website, such as yourdomain.com/menu. A PDF works too if its address never changes.
  2. Make a static code for that address. The link is stored in the code itself, so no vendor sits between the table and your menu.
  3. Check the print size. Leave a quiet zone of four modules and keep at least 4 printer dots per module (DENSO WAVE).
  4. Update the page, not the code. When prices change, replace the menu at the same address. The printed codes keep working.

Questions

Do I need a dynamic code to change my menu later?

No. Print a static code for a page you control and change the page. A dynamic code is only needed if you want the vendor to change where the code goes, or to count scans.

What if I post the menu as a PDF?

Keep the same file address when you upload a new version. If the address changes, the printed code points at the old one.
