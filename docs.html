Using the tools from code

Every tool on Toll that has an API works the same way: one HTTPS call with your key, a JSON answer, and a charge in real money from your balance.

New to the API? The quick start makes a real call in three steps, with samples in curl, JavaScript and Python.

Start here

  1. Create an account. You get a small free allowance each month, so you can try any tool before you pay.
  2. Add money when you need more. It is a one-time payment: no subscription, and no automatic top-up.
  3. Create an API key on your account page and send it with each call.

API keys

Keys start with tk_live_. Send yours in the Authorization header:

Authorization: Bearer tk_live_...

We show a key once, when you create it. We store only a fingerprint, so if you lose a key, revoke it and make a new one. Make one key per app or agent, so you can limit or revoke each on its own. Keep keys on your server, never in a web page or a public repository.

Pricing and balance

Most tools have a fixed price per call, in US dollars and in Indian rupees. Some price what you ask for: per row, per document, with free repeats of the same job for a while, cheaper rates past a volume in a month, or a monthly ceiling. Each tool's page and its entry in the tools endpoint say every price in words, and a quote (below) tells you the exact amount before you run anything. Your account has one currency, chosen when you sign up, and every price and charge you see is in that currency. Prices are real money, often fractions of a cent, like $0.0005, not points or tokens.

Your balance has two parts:

Free allowance
Given to every account on the 1st of each month (UTC). We spend it first. Whatever is left expires at the end of the month.
Paid balance
Money you added. It never expires.

A tool that bills for what it delivers (for example, only definitive answers in a batch) takes the full amount when the call starts and refunds the rest in the same response; charged.reserved and charged.refunded show both. A charge that is refunded unless something happens later (such as a form being signed) says by when in charged.refundedUnlessConfirmedBy.

A refund always returns money to the part it came from. Paid money comes back to your paid balance in full, whenever the refund happens. Free allowance from a month that has already ended comes back and expires again straight away, as it would have at the end of that month.

We only charge for calls that succeed. A call with invalid input is refused before any charge. If a tool fails while it runs, we refund the charge straight away and the response says so.

Spending limits

Every key has a monthly limit, and you can set one for the whole account too. Limits are hard: if a call would take this month's spending past a limit, we refuse it with cap_reached and charge nothing. Limits count from the 1st of each month (UTC). Change them any time on your account page.

Making a call

Send a POST with a JSON body to the tool's endpoint:

/toll-preview/api/v1/tools/tool-slug

A successful call answers with the result, what it cost, and your balance after the charge:

{
  "ok": true,
  "result": { ... },
  "charged": { "amount": 500, "currency": "USD", "display": "$0.0005" },
  "balance": { "total": 19999500, "display": "$19.9995" },
  "dataVersion": "holiday-rules-2026.10"
}

To know the price first, send the same body to /toll-preview/api/v1/tools/tool-slug/quote. It answers with quote.amount, quote.display and the price in words, and runs, charges and reserves nothing. Over MCP, the quote_price tool does the same.

Amounts are whole numbers of micro-units: one dollar or one rupee is 1,000,000. The display fields show the same amount as text. dataVersion names the reference data the answer came from, when a tool uses any.

Each tool page has ready-to-copy examples in curl, JavaScript, Python and MCP. The full machine-readable description is the OpenAPI document, and the tool list is at the tools endpoint.

Errors

Every error has the same shape. fields appears when specific input fields were wrong.

{
  "ok": false,
  "error": { "code": "invalid_input", "message": "...", "fields": { "start": "..." } }
}
StatusCodeWhat it means
400invalid_inputThe body is not valid JSON, is too large, or does not match the tool's input. Not charged.
401unauthorizedThe key is missing, wrong or revoked.
402insufficient_balanceYour balance does not cover this call. Add money and try again.
402cap_reachedThe call would pass a monthly limit on the key or the account. Not charged.
404unknown_toolNo tool has that slug, or it has been retired.
409in_progressA call with the same Idempotency-Key, or the first paid call for the same job, is still running. Retry in a moment.
422idempotency_mismatchThe Idempotency-Key was already used with different input.
422not_availableThe tool cannot answer this exactly (for example, no published data for that date), or it only runs in the browser. Not charged.
429rate_limitedToo many requests. Slow down and retry.
502upstream_failedThe tool failed while running. The charge was refunded.

Idempotency

Networks drop answers. To retry safely, send an Idempotency-Key header with a value you choose (1 to 200 characters), unique per logical call:

Idempotency-Key: invoice-4471-due-date

If we have already answered a call with that key for the same tool, we send the stored answer again, mark it with Idempotent-Replay: true, and charge nothing more. Reusing a key with different input returns idempotency_mismatch. If the first call failed and was refunded, the key is free to use again.

Rate limits

Each key can make 10 requests a second, with short bursts of up to 20. Past that you get rate_limited; wait briefly and retry.

On the website, people who are not signed in get a few free runs each day. Signed-in runs on the website are charged like API calls.

MCP for AI agents

Agents that speak the Model Context Protocol can use every API tool through one endpoint, over Streamable HTTP:

/toll-preview/mcp

Add it to your MCP client with your key as a Bearer token:

{
  "mcpServers": {
    "tools": {
      "type": "http",
      "url": "/toll-preview/mcp",
      "headers": { "Authorization": "Bearer YOUR_API_KEY" }
    }
  }
}

Listing tools needs no key; calling one does. Each tool's MCP name is its slug, its input schema is the same as the API's, and calls are priced and limited exactly like API calls. When a call is refused (for example, a limit is reached), the agent gets the reason as text it can act on.
