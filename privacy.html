Privacy

What we keep, and why

This page lists what Toll stores when you use it, in plain words. It describes what the software does today. Toll is run by Conyso.

The short version

  • There are no ad or analytics trackers, and no third-party scripts, on any page except the Razorpay payment page.
  • Your IP address is never written to our database. We only use it, for the day, to make the visitor hash described below.
  • What you type into a tool is used to work out the answer. It is not stored, with one exception for API retries, explained below.
  • The image tool runs in your browser. Your image never leaves your device.

If you create an account

We store your email address, a hash of your password (never the password itself), the currency you chose, the monthly spending limit you set, and when you signed up.

We also keep a ledger of your balance: each top-up, each monthly free allowance, each charge and each refund, with the amount, the tool, the API key that made the call, and the time. The ledger does not hold what you asked the tool.

One cookie, for signing in

When you sign up or sign in, we set one cookie so the site knows it is you. Scripts on the page cannot read it, and it is only sent to this site. It lasts 30 days, or until you sign out. We store only a hash of its value, so the cookie cannot be rebuilt from our database.

There are no other cookies, and the pages do not use your browser's local storage.

API keys

We show a new key once. After that we keep only a hash of it, plus its first 12 characters so you can tell your keys apart. We also keep the name you gave it, its monthly limit, when it was made, when it was last used, and when it was revoked.

Free runs without an account, and sign-up limits

Without an account you get 5 free runs a day, and one visitor can create at most 3 accounts a day. To count these we make a visitor hash from the date, your IP address and a secret only the server knows. We store that hash with a count for the day. The hash changes every day, and rows from earlier days are deleted as soon as the next day's first free run or sign-up is recorded.

The same daily hash is used, in memory only, to slow down repeated sign-in attempts and page-view beacons. Those counts are never written to the database.

Page views and usage counts

Our pages send one page-view event when they load. It records which tool page it was (if any), your account if you are signed in, and the time. It records no inputs, no IP address and no browser details.

We also count runs, charges, sign-ups and top-ups the same way: which tool, which account, whether it came from the website, the API or MCP, and when.

What you send to a tool

When you run a tool on its page, through the API or over MCP, your input goes to our server, which works out the answer and sends it back. We do not store the input.

The one exception: if you send an Idempotency-Key header with an API call, we keep a hash of the input and the answer we gave, so a retry with the same key gets the same answer and is not charged twice.

Payments

Rupee top-ups are paid through Razorpay. The payment page loads Razorpay's checkout script and passes it your email address so you do not have to type it. Your card or bank details go to Razorpay, never to us. From Razorpay we keep the payment's ID, amount and currency, and our own record of the top-up: its amount, reference and status.

Dollar top-ups are not open yet.

Tool requests

If you use the form to ask for a tool we do not have, we store what you wrote and, if you gave one, your email address.
