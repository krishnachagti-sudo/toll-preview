SPF lookup counter

Enter a domain. It walks the SPF record the way RFC 7208 says a receiver does: every include, nested ones too, every a, mx, ptr, exists and redirect, numbered in order. You see the count out of 10, which term would be the 11th, the void lookups (limit 2), and what each include costs. Give a sending IP to see what a receiver would actually decide for it.

  • Lookup count for one domain or draft record: $0.002 per check for the first 10,000 each calendar month, then $0.001 per check.
  • Batch of up to 50 domains: $0.002 per domain for the first 10,000 each calendar month, then $0.001 per domain; you pay only for what is delivered and the rest is refunded at once.
  • Macro explanation (no DNS): free.

Without an account you get 5 free checks a day. Macro explanations are free and run in your browser.

How it counts

  • Counted: include, a, mx, ptr, exists and redirect, across the whole check, nested records included. The 11th gives permerror (RFC 7208 Section 4.6.4).
  • Not counted: ip4, ip6, all and exp. Terms after "all", and a redirect in a record that has "all", are never evaluated.
  • Void lookups: a term whose query finds nothing. Receivers SHOULD stop at 2; some do not enforce it.
  • Macros: a term like exists:%{i}._spf.example.com is counted as 1. Without a sending IP its name cannot be built, so it is not followed; with one, it is.
  • Worst case and path taken: the count walks every term. A receiver stops at the first match, so with a sending IP you also get the result and the lookups for that IP.

Answers come from public DNS (the resolver and time are shown with each result) and change when providers change their records. Counts follow RFC 7208; receivers may differ on SHOULD rules such as the void lookup limit. SPF is one of several checks a receiver makes, so passing it does not guarantee delivery. Private, internal and special-use names are never queried.
