    The rules

    How it reads a report, and names the sender.

    DMARC passes on aligned DKIM or aligned SPF; a source is named only from dated, published provider data.

    What it does not cover

    It does not prove who sent the mail: an unnamed source stays unnamed. Check before you change DNS.

    Read the full list

    Source names are inferred from dated, published provider data, with the evidence shown; shared infrastructure can carry several companies' mail. Check before you change DNS.

    An IP in Amazon Web Services or Google Cloud's published ranges is a rented server there, not a named service. Nothing else is guessed: an unnamed source is unnamed, not called spoofing.

    Both formats

    RFC 9990 and RFC 7489, with each reporter's real quirks handled.

    RFC 9990

    Read the full rules

    RFC 9990 (May 2026, namespace urn:ietf:params:xml:ns:dmarc-2.0) and RFC 7489 Appendix C, which most reporters still send. Each reporter's real quirks are handled: Google's .zip, Microsoft's and Mail.ru's next-midnight end time, Yahoo's trailing tabs, GMX's namespace.

    When DMARC passes

    Aligned DKIM or aligned SPF, as the receiver reports it. When both fail, the raw results say why.

    Read the full rules

    DMARC passes when the receiver reports aligned DKIM or aligned SPF (policy_evaluated). When both fail, the raw results (auth_results) say why: a signature for another domain, SPF for the service's bounce domain, a broken signature, or an IP not in your SPF record.

    Naming the source

    A provider's own published IP ranges first, then a signing or SPF domain its documentation names.

    Read the full rules

    An IP inside the ranges a provider publishes in its own SPF record names that provider (record measured November 7, 2026). A passing signature or SPF check for a domain a provider's own documentation names comes next. An IP in Amazon Web Services or Google Cloud's published ranges is a rented server there, not a named service. Nothing else is guessed: an unnamed source is unnamed, not called spoofing.

    Safe by design

    No DOCTYPE, capped decompression, and reports read in memory and not kept.

    Read the full rules

    The XML reader refuses any DOCTYPE, so no entity is declared or fetched; decompression stops at 32 MB per report and at 250 times the file's size; a zip is read in memory, and only its .xml files.

    Reports are processed in memory and not kept.
