# 552 5.3.4: what it means and what to do

552 5.3.4 is a policy rejection: IANA defines X.3.4 as "Message too big for system"; do not suppress the address; fix the sending setup. Gmail publishes 1 text with it.

- Verdict on its own: policy
- Published texts: 1

## The codes, part by part

| Part | Value | Meaning | Source |
| --- | --- | --- | --- |
| Reply code | `552` | Requested mail action aborted: exceeded storage allocation | RFC 5321 |
| Class | `5.X.X` | Permanent Failure | RFC 3463 |
| Subject | `X.3.X` | Mail System Status | RFC 3463 |
| Detail | `X.3.4` | Message too big for system | RFC 3463 |

**IANA X.3.4:** The message is larger than per-message size limit. This limit may either be for physical or administrative reasons. This is useful only as a permanent error.

IANA lists the reply codes used with it as: undefined.

## What to do

**Policy.** Do not suppress the address: a rule your sending setup breaks (authentication, TLS, format, size or relay) refused it. Fix the setup, then resend.

## Questions

### What does 552 5.3.4 mean?

The reply code 552 means "Requested mail action aborted: exceeded storage allocation" (RFC 5321). The enhanced code 5.3.4 is IANA X.3.4, "Message too big for system", in class 5 (Permanent Failure).

### Is 552 5.3.4 a hard or soft bounce?

It is classed policy: Keep the address. Fix the sending setup (authentication, TLS, size, format or relay), then resend.
