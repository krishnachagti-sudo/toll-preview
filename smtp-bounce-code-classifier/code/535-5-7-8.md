# 535 5.7.8: what it means and what to do

535 5.7.8 is a policy rejection: IANA defines X.7.8 as "Authentication credentials invalid"; do not suppress the address; fix the sending setup.

- Verdict on its own: policy

## The codes, part by part

| Part | Value | Meaning | Source |
| --- | --- | --- | --- |
| Reply code | `535` | Authentication credentials invalid | RFC 4954 |
| Class | `5.X.X` | Permanent Failure | RFC 3463 |
| Subject | `X.7.X` | Security or Policy Status | RFC 3463 |
| Detail | `X.7.8` | Authentication credentials invalid | RFC 4954 |

**IANA X.7.8:** This response to the AUTH command indicates that the authentication failed due to invalid or insufficient authentication credentials. In this case, the client SHOULD ask the user to supply new credentials (such as by presenting a password dialog box).

IANA lists the reply codes used with it as: undefined.

## What to do

**Policy.** Do not suppress the address: a rule your sending setup breaks (authentication, TLS, format, size or relay) refused it. Fix the setup, then resend.

- [IANA: SMTP Enhanced Status Codes registry (updated December 6, 2024), read November 8, 2026](https://www.iana.org/assignments/smtp-enhanced-status-codes/smtp-enhanced-status-codes.xml)
- [RFC 3463: Enhanced Mail System Status Codes, read November 8, 2026](https://www.rfc-editor.org/rfc/rfc3463.txt)
- [RFC 5321: Simple Mail Transfer Protocol, read November 8, 2026](https://www.rfc-editor.org/rfc/rfc5321.txt)

> Verdicts follow the RFCs, the IANA registry and each provider's published texts as read on November 8, 2026; receivers change their texts without notice. Suppression is your decision: a verdict is a rule-based recommendation, not proof that an address is valid or invalid.

## Questions

### What does 535 5.7.8 mean?

The reply code 535 means "Authentication credentials invalid" (RFC 4954). The enhanced code 5.7.8 is IANA X.7.8, "Authentication credentials invalid", in class 5 (Permanent Failure).

### Is 535 5.7.8 a hard or soft bounce?

It is classed policy: Keep the address. Fix the sending setup (authentication, TLS, size, format or relay), then resend.
