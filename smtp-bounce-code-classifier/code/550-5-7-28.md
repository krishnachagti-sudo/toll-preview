# 550 5.7.28: what it means and what to do

550 5.7.28 is a block: IANA defines X.7.28 as "Mail flood detected"; do not suppress the address; fix the sender's reputation, content or volume. Gmail publishes 1 text with it.

- Verdict on its own: block
- Published texts: 1

## The codes, part by part

| Part | Value | Meaning | Source |
| --- | --- | --- | --- |
| Reply code | `550` | Requested action not taken: mailbox unavailable (e.g., mailbox not found, no access, or command rejected for policy reasons) | RFC 5321 |
| Class | `5.X.X` | Permanent Failure | RFC 3463 |
| Subject | `X.7.X` | Security or Policy Status | RFC 3463 |
| Detail | `X.7.28` | Mail flood detected | draft-levine-mailbomb-header-00 |

**IANA X.7.28:** The message appears to be part of a mail flood of similar abusive messages.

IANA lists the reply codes used with it as: undefined.

## What to do

**Block.** Do not suppress the address: the receiver refused the sender (reputation, content or volume). Fix that, then resend.

## Questions

### What does 550 5.7.28 mean?

The reply code 550 means "Requested action not taken: mailbox unavailable (e.g., mailbox not found, no access, or command rejected for policy reasons)" (RFC 5321). The enhanced code 5.7.28 is IANA X.7.28, "Mail flood detected", in class 5 (Permanent Failure).

### Is 550 5.7.28 a hard or soft bounce?

It is classed block: Keep the address. Fix what the receiver objects to in the sender (reputation, content, volume), then resend.
