# 452 4.2.2: what it means and what to do

452 4.2.2 is a soft bounce: IANA defines X.2.2 as "Mailbox full"; retry with backoff and suppress only after repeated failures. Gmail publishes 1 text with it.

- Verdict on its own: soft
- Published texts: 1

## The codes, part by part

| Part | Value | Meaning | Source |
| --- | --- | --- | --- |
| Reply code | `452` | Requested action not taken: insufficient system storage | RFC 5321 |
| Class | `4.X.X` | Persistent Transient Failure | RFC 3463 |
| Subject | `X.2.X` | Mailbox Status | RFC 3463 |
| Detail | `X.2.2` | Mailbox full | RFC 3463 |

**IANA X.2.2:** The mailbox is full because the user has exceeded a per-mailbox administrative quota or physical capacity. The general semantics implies that the recipient can delete messages to make more space available. This code should be used as a persistent transient failure.

IANA lists the reply codes used with it as: undefined.

## What to do

**Soft bounce.** Retry with backoff; suppress the address only if it keeps failing over several days.

## Questions

### What does 452 4.2.2 mean?

The reply code 452 means "Requested action not taken: insufficient system storage" (RFC 5321). The enhanced code 4.2.2 is IANA X.2.2, "Mailbox full", in class 4 (Persistent Transient Failure).

### Is 452 4.2.2 a hard or soft bounce?

It is classed soft: Retry with backoff; suppress only after repeated failures over several days.
