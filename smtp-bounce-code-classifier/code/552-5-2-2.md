# 552 5.2.2: what it means and what to do

552 5.2.2 is a soft bounce: IANA defines X.2.2 as "Mailbox full"; retry with backoff and suppress only after repeated failures. Gmail and Microsoft publish 2 texts with it, classed hard, policy: classify the full reply.

- Verdict on its own: soft
- Published texts: 2

## The codes, part by part

| Part | Value | Meaning | Source |
| --- | --- | --- | --- |
| Reply code | `552` | Requested mail action aborted: exceeded storage allocation | RFC 5321 |
| Class | `5.X.X` | Permanent Failure | RFC 3463 |
| Subject | `X.2.X` | Mailbox Status | RFC 3463 |
| Detail | `X.2.2` | Mailbox full | RFC 3463 |

**IANA X.2.2:** The mailbox is full because the user has exceeded a per-mailbox administrative quota or physical capacity. The general semantics implies that the recipient can delete messages to make more space available. This code should be used as a persistent transient failure.

IANA lists the reply codes used with it as: undefined.

## What to do

**Soft bounce.** Retry with backoff; suppress the address only if it keeps failing over several days.

## Questions

### What does 552 5.2.2 mean?

The reply code 552 means "Requested mail action aborted: exceeded storage allocation" (RFC 5321). The enhanced code 5.2.2 is IANA X.2.2, "Mailbox full", in class 5 (Permanent Failure).

### Is 552 5.2.2 a hard or soft bounce?

It depends on the text: on its own the code is classed soft, but the texts published with it are classed hard, policy. Classify the full reply.
