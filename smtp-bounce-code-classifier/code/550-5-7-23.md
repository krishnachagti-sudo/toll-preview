# 550 5.7.23: what it means and what to do

550 5.7.23 is a policy rejection: IANA defines X.7.23 as "SPF validation failed"; do not suppress the address; fix the sending setup. Microsoft publishes 1 text with it.

- Verdict on its own: policy
- Published texts: 1

## The codes, part by part

| Part | Value | Meaning | Source |
| --- | --- | --- | --- |
| Reply code | `550` | Requested action not taken: mailbox unavailable (e.g., mailbox not found, no access, or command rejected for policy reasons) | RFC 5321 |
| Class | `5.X.X` | Permanent Failure | RFC 3463 |
| Subject | `X.7.X` | Security or Policy Status | RFC 3463 |
| Detail | `X.7.23` | SPF validation failed | RFC 7372, RFC 7208 |

**IANA X.7.23:** This status code is returned when a message completed an SPF check that produced a "fail" result, contrary to local policy requirements. Used in place of 5.7.1 as described in .

IANA lists the reply codes used with it as: undefined.

## What to do

**Policy.** Do not suppress the address: a rule your sending setup breaks (authentication, TLS, format, size or relay) refused it. Fix the setup, then resend.

## Questions

### What does 550 5.7.23 mean?

The reply code 550 means "Requested action not taken: mailbox unavailable (e.g., mailbox not found, no access, or command rejected for policy reasons)" (RFC 5321). The enhanced code 5.7.23 is IANA X.7.23, "SPF validation failed", in class 5 (Permanent Failure).

### Is 550 5.7.23 a hard or soft bounce?

It is classed policy: Keep the address. Fix the sending setup (authentication, TLS, size, format or relay), then resend.
