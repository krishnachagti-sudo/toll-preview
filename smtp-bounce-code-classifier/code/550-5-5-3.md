# 550 5.5.3: what it means and what to do

550 5.5.3 is a policy rejection: IANA defines X.5.3 as "Too many recipients"; do not suppress the address; fix the sending setup. Gmail publishes 1 text with it.

- Verdict on its own: policy
- Published texts: 1

## The codes, part by part

| Part | Value | Meaning | Source |
| --- | --- | --- | --- |
| Reply code | `550` | Requested action not taken: mailbox unavailable (e.g., mailbox not found, no access, or command rejected for policy reasons) | RFC 5321 |
| Class | `5.X.X` | Permanent Failure | RFC 3463 |
| Subject | `X.5.X` | Mail Delivery Protocol Status | RFC 3463 |
| Detail | `X.5.3` | Too many recipients | RFC 3463 |

**IANA X.5.3:** More recipients were specified for the message than could have been delivered by the protocol. This error should normally result in the segmentation of the message into two, the remainder of the recipients to be delivered on a subsequent delivery attempt. It is included in this list in the event that such segmentation is not possible.

IANA lists the reply codes used with it as: undefined.

## What to do

**Policy.** Do not suppress the address: a rule your sending setup breaks (authentication, TLS, format, size or relay) refused it. Fix the setup, then resend.

## Questions

### What does 550 5.5.3 mean?

The reply code 550 means "Requested action not taken: mailbox unavailable (e.g., mailbox not found, no access, or command rejected for policy reasons)" (RFC 5321). The enhanced code 5.5.3 is IANA X.5.3, "Too many recipients", in class 5 (Permanent Failure).

### Is 550 5.5.3 a hard or soft bounce?

It is classed policy: Keep the address. Fix the sending setup (authentication, TLS, size, format or relay), then resend.
