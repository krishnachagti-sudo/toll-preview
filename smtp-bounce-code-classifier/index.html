What you get

Paste the raw SMTP reply, a delivery status notification (DSN) or a Postfix log line. You get the verdict, the rule that decided it, what the codes mean, and whether to suppress the address. Gmail's, Microsoft's and Yahoo's own published texts are read first, so a 550 5.7.26 is an authentication problem to fix, not an address to delete.

Without an account you get 5 free single bounces a day. Code lookups are free. Batches need an account.

What to classify

An SMTP reply, a whole DSN (Status and Diagnostic-Code lines) or a Postfix log line with dsn= and status=.

The rules

How it decides, in this order.

The provider's own text first, then the enhanced code, then the reply code. A 4xx is never hard.

What it does not cover

Texts in languages other than English, and changes a receiver makes after the dates shown. Suppression stays your decision.

Read the full note

Verdicts follow the RFCs, the IANA registry and each provider's published texts as read on the dates shown; receivers can change their texts at any time, and English texts only are matched. Suppression is your decision: the verdict is a rule-based recommendation, not proof that an address is valid or invalid. Every result names its rule, so you can override it in your own code.

  1. The provider's own text first. Gmail's SMTP error table (last updated October 26, 2026), Microsoft's Exchange Online NDR table, Microsoft's MTA-STS page and Outlook.com 5.7.515 notice, and Yahoo's Sender Hub error families, each read November 8, 2026. One code can carry several texts: Gmail publishes eight with 421 4.7.0.
  2. Then the enhanced status code. Every detail code in the IANA registry (updated December 6, 2024) has a verdict for class 4 and class 5. A code IANA does not list is judged by its subject (X.1 to X.7).
  3. Then the reply code (RFC 5321, RFC 7504, RFC 4954), then the class digit.
  4. A 4xx is never hard. RFC 3463 says a 4.X.X failure may succeed if sent again, so a 4xx can be soft, block or policy, never "suppress now".
  5. Ambiguous is never hard by accident. 5.0.0, 554 and unknown 5xx details are not treated as hard; a bare 550 with no enhanced code and no known text is, at low confidence, and says so.
